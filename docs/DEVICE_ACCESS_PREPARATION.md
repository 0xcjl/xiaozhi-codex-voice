# 实体设备接入准备

边界：本阶段不打开串口、不重置设备、不改设备地址、不改官方控制台、不刷固件，也不开放局域网监听。保留已有登录与隔离测试数据库。

1. 只读检查 USB 标识、固件配置入口与官方设备条目；不可仅凭 VID/PID 推定内存或设备身份。
2. 修复旧匿名 OTA 对订阅语音设备的令牌签发缺口：订阅设备必须另用设备专属凭据，不能仅凭 MAC 领取令牌。普通模型的已有 OTA 流程保持兼容。
3. 控制台加入只读接入检查，核对设备归属、连接选择、独立订阅授权、认证开关与设备入口；未完成设备专属凭据、网络可达及恢复地址核对时，不允许显示可切换。
4. 在隔离实例执行真实 Shiro、OTA 拒绝与 UI/构建回归，核对原 Codex 登录及回环监听保持不变。

后续实体切换必须先取得设备上的原 OTA 地址，给出目标入口与回退方法。当前没有获准修改设备或公开接口，不能擅自切换。

## 本轮实施与验收

- 新增独立设备凭据表（仅保存 SHA-256 摘要）；高熵接入地址只返回一次。兼容标准固件保存 WebSocket 凭据，不向设备下发订阅凭据。
- 设备凭据采用 30 天滑动租约：成功连接自动续期，长期离线过期可在控制台续期；已撤销或连接修订改变不能直接续期，必须轮换。活动连接每 10 秒复核，管理服务异常时关闭。
- 专属 OTA 仅返回 WebSocket 配置，不返回固件、MQTT 或激活码；匿名常规 OTA 不签发订阅权限。
- 控制台提供接入状态、生成/轮换、续期、撤销和原 OTA 记录。未核实原地址时回退状态必须明确未完成。
- 隔离全链路验收：真实 Shiro/MySQL/Redis、专属 OTA、首次绑定客户端、续期/过期/撤销/轮换、越权拒绝、真实订阅 WebRTC 音频与清理。仅重启本项目回环服务，不接实体设备。
- 实机限制：wha103 厂商配网按键与实际保存 OTA 未证明；上游默认 URL 仅为线索。
