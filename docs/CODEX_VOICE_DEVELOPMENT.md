# Codex 原声与小智控制台：开发和联调记录

状态快照：2026-10-30。项目暂停迭代，可据此恢复；仓库为实验性版本，不是生产部署说明。基于 xinnan-tech/xiaozhi-esp32-server 的上游基线 `1a095d5`；由于原开发副本是浅克隆，本仓库以完整源码快照发布，不包含上游完整 Git 历史。保留根目录 MIT 许可及上游版权。

## 目标与思路

保留小智设备已有协议和官方服务回退能力，自建控制台提供 API 模型与独立订阅连接选项；借助本机或云节点承载音频、上下文和任务状态，ESP32 负责采集及播放。目标包括自然插话、跨重连上下文、后台任务进度/结果、设备 MCP 和准确模型身份。Cloud 远端节点及 Grok Bot 尚未完成；API 模型选项的真实供应商调用尚未验收。

控制台管理接口负责身份、授权和配置；设备入口只开放有限的设备协议，不开放管理数据库、账号授权接口或 Codex RPC。每个控制台用户和服务连接使用独立 Codex profile；服务账号和日常 Codex 登录互不复用。订阅授权、账号登录、设备在线、实时语音可用分别是不同状态。

Codex 原生实时语音路径曾在独立账户的真实 Codex WebRTC 与实体设备上验证；这不等于 OpenAI 已提供面向第三方的 ChatGPT 产品语音订阅接口。实际支持情况取决于账户权限和当前 Codex 服务实现，不能将后台模型名称冒充未公开的声学模型名称，也不保证未来接口兼容。

## 架构

- `main/manager-web`：连接配置、模型选择与授权交互；`main/manager-api`：鉴权、连接配置、设备绑定和授权代理。
- `main/xiaozhi-server/core/providers/realtime`：设备 WebSocket/Opus、Codex WebRTC、账户隔离、任务派发与持久上下文、MCP 工具发现和控制回执。
- 独立线程复用；后台任务使用隔离工作目录，状态和报告在服务端持久化，设备不保存 OAuth 凭据或任务队列。报告先核验任务身份和数字，才发送原声。
- 设备工具以本次真实 MCP 回执为准；音量修改后再读回。原声短片段可在进程内按设备授权范围、模型、任务与完整文本匹配复用；最多 2 MiB、32 条、五分钟、每条六秒。复用声音不跳过设备操作与读回。

## 遇到的问题和处理

1. **WebRTC 控制通道超时**：媒体/DTLS 可连接，但双方同时发起 SCTP 导致状态停留在 COOKIE-WAIT/COOKIE-ECHOED。针对 aiortc 1.15.0 的私有实现增加碰撞处理、阶段超时和受控重试，并清理连接候选任务。版本升级须重做协议回归；见 [握手记录](CONTROL_CHANNEL_STABILITY.md)。
2. **中断与错误回执**：音频传输和播放状态分开，设备显式 abort 时中断；被打断的已核验报告在回答插话后恢复。并发报告绑定任务身份，拒绝错误或额外数值，不把未确认内容当作已送达。
3. **设备控制与型号**：工具发现必须以固件实际清单为准，读回不一致时不能声称设置成功；模型查询应取服务实际返回的后台/任务执行身份。曾因任务状态报告抑制型号答复、中文紧邻 GPT 型号导致校验误判，已增加独立答复及回归测试。详见 [设备 MCP](DEVICE_MCP_RUNTIME.md)。
4. **确认等待**：完整原声生成和核验产生延迟；单一音量设置在读回后提前排队，短报告允许受控缓存。测试中本机首次确认中位由 10.978 秒降至 8.232 秒，重复原声中位 3.952 秒；另一次公网首次仍为 10.712 秒。测量从转写完成到首个 Opus 帧，不包含识别耗时；样本量小，不是 SLA。
5. **测试和听感**：浏览器播放器静音、无声但有文字、环境音误触发中断及报告转写偏差都曾出现。自动化必须检查解码音频、用户插话与结果身份；自动化通过不等于实体扬声器或自然运行验收。
6. **剩余问题**：公网首次派发长尾未解决；探索性长复合任务输入曾无转写，原因未确认。新项目控制台的独立订阅账户尚未授权，新环境尚未重做实体语音或全天候稳定性验收。历史文档是有日期的阶段记录，与本节最新状态不一致时以本节及代码实测为准。

## 验证快照

新隔离控制台：独立前端、Java/Maven、MySQL 和 Redis，均只监听本机；前端构建通过，10 项契约与 83 项单元测试通过；Java 后端 246 项测试通过；Python 实时模块 151 项单元及 50 项集成通过。真实管理 API、独立数据库及 Redis 的 14 项权限、连接配置与模拟设备联调通过，独立服务停止重启后复测通过。测试管理员与临时数据库不随仓库发布。

此前设备侧记录包括可逆回退、模拟公网六分钟与六轮上下文检查，以及真实本机 Codex CLI 任务与插话恢复；这些是当时的测试结果，不构成新安装的验收，也不能证明任意网络或设备稳定。禁止把页面有文字、握手成功、模型配置值或 API 登录状态当作已听到正确语音。

## 本地开发与安全

1. 按上游 README 配置工具；具体版本、依赖和系统要求以仓库文件为准。在隔离环境运行，测试数据库、Redis、账号和端口均需自行建立，不要指向已有设备或生产配置。
2. `main/xiaozhi-server/requirements-codex-realtime.txt` 提供实时路径的隔离依赖；在对应项目目录运行 `python -m unittest discover -s tests/core/providers/realtime -p 'test_*.py'` 和 `python -m unittest discover -s tests/core/providers/realtime/integration -p 'test_*.py'`。
3. 控制台分别执行前端 `npm ci --ignore-scripts`、`npm test`、`npm run build`；后端使用 Java 21、Maven 和明确隔离的 MySQL/Redis 测试配置，再执行测试。首次直接使用上游默认数据库配置的后端测试失败，改为隔离配置后通过。
4. 不提交 `auth.json`、OAuth token、设备令牌、数据库密码、私有 OTA 地址、真实设备标识、运行日志或用户音频；账号服务和数据库切勿暴露公网。实机操作前确认固件能力、授权、备份与可逆回退。
5. 下一轮优先定位公网首次派发耗时及长复合任务未转写；以不同语句、多次重连、明确任务和数字核验验证。真人、实体、订阅授权与生产部署应分别获得授权和分别验收。
