# 设备 MCP、模型身份与控制回执

本功能属于独立订阅语音运行时。设备继续运行原小智固件；设备 MCP 经已有、已认证的 WebSocket 转发，不需要向 ESP32 放入任务队列、Codex 凭据或整段报告音频。

## 工具发现和边界

服务在设备 `hello` 后发送 MCP `initialize` 和分页 `tools/list`，接收循环独立处理 JSON-RPC 回执。请求编号和等待者仅属于当前连接；最多 8 个等待者，单次请求 8 秒，迟到回执不能确认另一个请求。连接关闭释放等待者，写操作不自动重试。

只转发固件实际报告且在服务允许清单中的工具：状态、音量、主题、亮度（如支持）、闹钟增删查、重新配网、系统信息及屏幕信息。实机 WHA103 报告了其中 9 项，没有亮度工具；不会伪装成支持亮度。固件升级、任意资源下载地址和通用重启不向语音端开放。

设备描述不会直接成为模型的工具说明；模型看到服务维护的说明及经裁剪的参数结构。每次调用重新核验设备授权，检查类型、枚举、参数范围。音量拒绝布尔值、非整数和 0..100 以外数值。设置音量前读取状态，设置后再次读回，只有读回一致才确认设置成功。

## 同一会话获得新增工具

Codex `thread/resume` 不接受新增 `dynamicTools`。因此设备工具通过本连接临时 stdio MCP 服务注册，而四项后台任务动态工具继续保留。恢复会话之前检查 MCP 注册，恢复之后再检查该线程自己的 MCP 清单，随后启动原声；保留同一 `threadId`。

MCP 代理只连接 127.0.0.1 的随机端口，以每次连接新生成的临时随机凭据认证。私有状态目录内的连接控制文件权限为 0600，断开时仅删除本连接仍持有的文件。设备独立凭据仍需经管理服务核验；此本机凭据不能越过设备授权。临时 CLI 参数逐项允许清单中的 MCP 工具，不给其他服务器统一放开授权，不写入日常 Codex 配置。

## 模型查询与任务记录

`model_info` 区分：

- `backingModel`：这次 `thread/start` 或 `thread/resume` 实际返回的对话后台模型；当前要求 `gpt-6.1-terra`，不接受静默降级。
- `workerConfiguredModel`：后台执行器配置，不能把它冒充某个旧任务的执行证据。
- `tasks[].execution`：任务启动时核对并保存的本机 Codex CLI、实际模型、工作线程 ID 和证据来源。没有执行记录的历史任务返回空对象，不追填猜测值。
- `realtimeAcousticModel`：服务未公开可核验编号，返回 null。不能把后台 Terra 型号当作声学引擎型号。

查询模型不创建任务，也不重放历史报告。复合追问同时查询任务状态和执行型号时，本次 `model_info` 的核验摘要独立进入原声答复队列，避免任务状态的专属报告使型号答复被吞掉；不把配置型号冒充实际执行型号。常规当前模型问题可以从已核验的连接身份直接回答。旧上下文缺失时交给同一个 backing 线程核查，不声称已经开新会话。

## 控制结果与语音

设备控制类用户发问后，未经确认的原声先行答复不发给设备，避免先说“已设置”而工具尚未执行。backing turn 没有本次 MCP 成功回执时只报告未确认；音量使用实际读回摘要。核验报告完成后释放播放抑制，保留下一轮普通对话和插话能力。15 秒未获回执会排队一次未确认提示，不自动重试设置。

重新配网会使固件正常重启或断开网络，因而可能来不及返回 MCP 结果。发送请求、收到回执、实机显示热点和成功读取配网页是不同证据；不得仅因断线声称完成，也不得自动重发。必要时按用户已授权的回退流程观察热点和配网页。

单一绝对音量命令在本次 MCP 设置及读回一致时即可排队简短原声确认，不再额外等待 backing turn 的最终文字；不会由转写直接重复派发写操作，backing 最终消息也不重复排队。混合命令、否定、相对音量或读回不一致时不走此快速路径。

原声报告仍先在 Mac 内存生成并核对数字，再按 Opus 下发。数字须完整一致，额外金额或模型后缀不符也会拒绝；允许原声重复说明同一已核验模型及其版本号。已经核验的短原声可在相同设备授权范围、后台模型、完整文本及任务身份内复用，最长五分钟；全运行时最多 32 条、2 MiB，每条不超过六秒，仅在 Mac RAM 中保存，不落盘、不占 ESP32 任务内存。复用声音不复用设备状态，每次设置仍重新执行并读回。播报被打断可复用已核验的完整片段，仍遵守插话和持久回执队列。

这保证数字核对的同时会增加答复等待时间。`connection-timings.jsonl` 只保存时间、固定工具名和音量读回值等诊断信息，不记录凭据、OTA 地址、原始录音或对话文本；上限 2 MiB，不能将短提示音的时间当作完整报告耗时。

## 联网与后台任务

普通实时信息查询在当前 backing 会话使用 `web_search="live"`，不创建后台任务。后台执行器继续关闭网络和 Web search，在独立任务目录工作。任务工具检查最近的真实用户发问是否明确涉及后台工作或文件/脚本任务；普通查询误派为后台任务时返回拒绝原因，并允许当前会话继续正常回答。搜索成功也不等于拿到了交易所实时行情，必须说明来源及报价时间。

## 自动化检查

在 `main/xiaozhi-server` 目录，使用项目已安装的独立虚拟环境：

```sh
../../../xiaozhi-codex-realtime-venv/bin/python -m unittest discover -s tests/core/providers/realtime -p 'test_*.py'
../../../xiaozhi-codex-realtime-venv/bin/python -m unittest discover -s tests/core/providers/realtime/integration -p 'test_*.py'
```

实机回退、长时间公网连接和真人听感的证据另存项目输出目录。单元/合成音频通过不能替代物理扬声器和固件行为的验收。
